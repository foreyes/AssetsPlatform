# 自包含静态资产接入标准

本标准用于维护者将**有权使用**的一组自包含 GLB 与独立 2D 原图整理为 `apps/reviewer/` 可读取的静态目录。它规范身份、依赖、证据和验证，不提供源工程提取器、后台上传器或授权判断。可运行字段见 [数据契约](DATA-CONTRACT.md)，操作见 [产品手册](PRODUCT-MANUAL.md)。

## 准入

1. 确认每个输入文件的使用、改编和再分发范围；私人源路径、凭据与无关文件不得加入公开目录。目录维护者只读取受信任的数据文件，不执行资产包中的程序、宏、安装脚本或编辑器扩展。
2. 为项目、数据集、每个物件及技术资源分配稳定唯一 ID；记录源文件的相对位置与内容摘要。文件名只帮助定位，不足以证明不同版本的同一性。
3. 对标准 glTF 关系记录实际引用：场景根→节点→mesh/primitive→材质→纹理→内嵌图像。共享图像保留共享引用；同 mesh 变体不盲目合并语义。无法解析的扩展依赖保持未知，不能宣称依赖闭合。
4. 独立图片只有被明确登记为物件或 sprite/UI 原图时才算 2D 物件；模型贴图仍是技术资源。缩略图不能充当已核对的原图。
5. 为每个条目分开记录索引、CPU 解析、WebGL 加载、材质/像素外观、动画来源与播放的状态和证据。缺失证据为未知，不自动等同失败或通过。

## 处理顺序

先在仓库外的授权目录准备和校验 GLB/图片，再用 `npm run import:directory -- --source <文件夹> --output <仓库外新目录> --id <ID>` 生成独立审阅工作区；默认输入只读且输出必须是新目录。该导入器仅处理支持的自包含 GLB，不会自动扫描工程、联网、上传或运行输入脚本。手工接入时从自制 `demo-a/` 模板复制目录结构，更换所有身份与存储键，填写目录 JSON、核对相对资源 URL。不要仅复制显示名称或让两个项目复用存储键。

输入变更应形成新的目录数据集或明确迁移记录；选择/备注备份须核对项目与数据集。生产语义标签应经本地确定性事实提取、受控候选与人工复核；文件名、预览图文字、共享材质不能直接断言“食物”等类别。详见 [语义标注](SEMANTIC-ANNOTATIONS.md)。

## 必须验证与明确未验证

运行 `npm test` 检查目录契约、格式预算、拒绝错误、稳定 ID 和合成引用，再在有 WebGL 的浏览器核对每种代表性条目的实际展示、取消和缺失数据表现。需记录测试使用的数据集、浏览器与 GPU、确实看到的结果；不可只因 JSON 中存在 `modelUrl` 就写入已验证。浏览器显示不是源材质或其他软件渲染的逐像素复刻。自制动画的详细证据与 `pending` 基线步骤见 [动画示例](ANIMATION-EXAMPLE.md)。

输出目录与原输入分开保存，且只发布有明确授权的文件。导出的审阅 JSON 不是模型备份；如需回滚源数据，应保留独立的原始文件版本和校验摘要。
